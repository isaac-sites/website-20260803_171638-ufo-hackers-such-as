## Introduction

A file found on a genuine government computer is not automatically a settled statement of government fact. Institutional networks contain working drafts, staff comments, training scenarios, simulated intelligence, test datasets, copied attachments and documents written by outside organisations. A dramatic phrase may be authentic in the narrow sense that it really appeared on an official server, yet still be preliminary, fictional, obsolete or unrelated to the meaning later assigned to it.



<img src="{{ "/assets/images/ufo_hackers_such_as_e2dece_government_file_misi_12aa80-overview.webp" | relative_url }}" alt="Overview image for File Context" loading="eager" decoding="sync" fetchpriority="high">

This distinction is crucial when assessing claims by UFO-motivated hackers such as Gary McKinnon. [Unauthorised access]({{ 'unauthorised-access/' | relative_url }}) might establish that someone reached a government system, but it does not establish the status, origin or intended meaning of every file encountered there. Without the surrounding folder structure, document history, authorship, dates, attachments and system purpose, apparently extraordinary material can be easy to misread. Archival and technical standards therefore treat provenance and context—not server ownership alone—as essential to understanding what a digital record actually represents.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://nvlpubs.nist.gov/nistpubs/SpecialPublications/1500-18/NIST.SP.1500-18r2.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: nvlpubs.nist.gov">[nist.gov]</a><span class="citation-popover" role="note"><span class="citation-popover-source">nvlpubs.nist.gov</span><span class="citation-popover-snippet">NIST PublicationsNIST Research Data Framework (RDaF)by VA Alexandria — Metadata and provenance comprise the information about a dataset t...</span></span></span>

## A Government Server Holds More Than Government Conclusions

Large public institutions use their networks as workplaces, not merely as repositories for approved policy. A single directory may contain final reports alongside early drafts, discarded alternatives, email attachments, administrative copies and background material submitted by contractors or other agencies.

This can produce a misleading chain of inference:


<div class="content-enhancement content-enhancement--step-flow" markdown="1">

1. The computer belongs to a military or intelligence organisation.
2. A document on it contains an unusual statement.
3. Therefore, the organisation officially accepts that statement as true.

</div>

The third step does not follow from the first two. The file may have been received rather than created by the organisation. It may record one employee’s suggestion, reproduce a press article, preserve an allegation for assessment or circulate an idea that was later rejected.

Government recordkeeping rules illustrate how varied official systems can be. The US Government Accountability Office notes that drafts distributed through email may themselves qualify as federal records and therefore require preservation. Their presence in an official recordkeeping environment does not turn them into final decisions; it shows that documentary systems preserve parts of the decision-making process as well as its eventual outcome.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.gao.gov/assets/a276567.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: gao.gov">[GAO]</a><span class="citation-popover" role="note"><span class="citation-popover-source">gao.gov</span><span class="citation-popover-snippet">GAO-08-742, Federal Records: National Archives and...June 13, 2008 — If agencies do not state that draft documents circulated on e-ma...</span><span class="citation-popover-meta">Published: June 13, 2008</span></span></span>

Another concerns a draft directive that still required circulation, discussion and approval. Both are genuine CIA records, but neither title alone would justify treating every sentence as adopted agency policy.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cia.gov/readingroom/document/cia-rdp80b01676r001200150044-7" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cia.gov">[CIA]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cia.gov</span><span class="citation-popover-snippet">PROPOSED REPLY TO PERSONAL LETTER FROM...This memorandum contains a recommendation for action on the part of the DCI. drafting a prop...</span></span></span>

The practical lesson is that authenticity and authority are separate questions. A file may be genuinely located within a government institution while lacking the approval, evidential support or organisational standing required to make it authoritative.

## Drafts, Simulations and Test Data Can Look Real

### Draft language records possibilities, not decisions

Drafts are often written in the same formal language and formatting as completed documents. They may carry classification markings, official templates, distribution lists and the names of senior offices. Those features can make an unfinished proposal appear conclusive when viewed in isolation.

Yet drafts frequently contain language that will be revised, qualified or removed. Staff may deliberately write a proposal in near-final form so that decision-makers can assess it. The CIA’s archived “Draft DCID 1/5”, for example, was accompanied by requests for approval and references to future consultation within the intelligence community. The file documents a stage in an institutional process rather than an unquestionable final position.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cia.gov/readingroom/document/cia-rdp83b01027r000100030034-7" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cia.gov">[CIA]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cia.gov</span><span class="citation-popover-snippet">DRAFT DCID 1/5 &#124; CIA FOIA (foia.cia.gov)Your approval of the attached draft DCID is requested prior to its circulation to the Communit...</span></span></span>

Draft collections may also preserve contradictory versions. A researcher who sees only one copy cannot safely assume it was the latest, that its recipient agreed with it or that it survived later review. Even official auditing standards distinguish completed supporting records from superseded drafts and notes reflecting incomplete or preliminary thinking.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.gao.gov/assets/cl_aicpa080626a.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: gao.gov">[GAO]</a><span class="citation-popover" role="note"><span class="citation-popover-source">gao.gov</span><span class="citation-popover-title">cl aicpa080626a</span><span class="citation-popover-snippet">Sherry Hazel Audit and Attest Standards...June 26, 2008 — The auditor need not include in audit documentation superseded drafts of worki...</span><span class="citation-popover-meta">Published: June 26, 2008</span></span></span>

For a hacker quickly browsing unfamiliar folders, these distinctions would be particularly difficult to reconstruct. The most surprising wording might come from the most speculative version rather than the version ultimately approved.

### Military systems deliberately contain fictional events

Defence organisations routinely create realistic fictional material for exercises. Command-post training may involve imaginary countries, simulated attacks, invented intelligence reports and “injects”—prepared events or messages introduced to force participants to make decisions.

US [military exercise]({{ 'exercise-files/' | relative_url }}) guidance describes scenario injects with identifiers, descriptions, intended recipients and a platform through which the fictional event will first be reported. In one African Lion exercise, the US Joint Staff supplied a fictional scenario that required personnel to plan activity across land, sea, air, cyberspace and space.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://oe.t2com.army.mil/site-content/OEE/Scenario%20Development/MCRP%207-20A.2.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: oe.t2com.army.mil">[oe.t2com.army.mil]</a><span class="citation-popover" role="note"><span class="citation-popover-source">oe.t2com.army.mil</span><span class="citation-popover-title">MCR P 7-20A.2 Event and Exercise Design</span><span class="citation-popover-snippet">MCR P 7-20A.2 Event and Exercise Design</span></span></span>

Exercise environments can mix several kinds of information:


<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* real personnel and unit names;
* actual communications systems;
* simulated threats and intelligence;
* computer-generated forces or targets;<span class="citation-chip-wrap"><a class="citation-chip" href="https://www.navy.mil/Press-Office/News-Stories/display-news/Article/3222751/us-uk-australian-and-canadian-forces-operate-as-a-combined-force-in-exercise-vi/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: navy.mil">[navy.mil]</a><span class="citation-popover" role="note"><span class="citation-popover-source">navy.mil</span><span class="citation-popover-snippet">Source details in endnotes.</span></span></span>
* fictional damage, casualties or movements;
* real-world geography adapted for training.

</div>

A US and allied exercise described by the Navy combined virtual participants with computer-generated threats. Earlier naval research also discussed integrating real and simulated targets when reconstructing exercises. A database extracted from such an environment could therefore contain plausible-looking operational records for events that never happened.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.onr.navy.mil/media/document/1990rptexercisereconstructionpdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: onr.navy.mil">[ONR]</a><span class="citation-popover" role="note"><span class="citation-popover-source">onr.navy.mil</span><span class="citation-popover-title">ONR90 EXERCISE RECONSTRUCTION</span><span class="citation-popover-snippet">ONR90 EXERCISE RECONSTRUCTION</span></span></span>

Some exercise messages are prominently marked as simulations, but that warning may appear in a header, accompanying instruction or related file rather than in every individual data entry. The US Navy has published exercise orders describing simulated hurricanes and earthquakes in the same urgent administrative style used for real emergencies. Detached from their “exercise” labels, portions of those messages could be mistaken for records of genuine disasters or secret operations.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.navy.mil/DesktopModules/ArticleCS/Print.aspx?Article=2235396&amp;ModuleId=791&amp;PortalId=1" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: navy.mil">[Navy]</a><span class="citation-popover" role="note"><span class="citation-popover-source">navy.mil</span><span class="citation-popover-snippet">Open source on navy.mil.</span></span></span>

### Test systems imitate operational systems

Government technical teams also use sample accounts, demonstration records and synthetic data when building or checking software. Test information is often designed to look realistic because unrealistic data cannot properly test search functions, reporting tools, security controls or database capacity.

The National Institute of Standards and Technology emphasises that data interpretation depends on metadata and provenance: information describing where a dataset came from, how it was produced and how it relates to other records. NIST also warns that questions of veracity, context and provenance become more serious when large datasets combine material from multiple systems and organisations.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://nvlpubs.nist.gov/nistpubs/SpecialPublications/1500-18/NIST.SP.1500-18r2.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: nvlpubs.nist.gov">[NIST Publications]</a><span class="citation-popover" role="note"><span class="citation-popover-source">nvlpubs.nist.gov</span><span class="citation-popover-snippet">NIST PublicationsNIST Research Data Framework (RDaF)by VA Alexandria — Metadata and provenance comprise the information about a dataset t...</span></span></span>

A spreadsheet containing unfamiliar officers, vessels, flights or destinations might therefore represent a software test, a planning model or a training population. Without the database schema, system documentation and production status, the entries cannot safely be read as a literal roster of real people or missions.

## Code Names Do Not Describe Their Subjects Literally

Government and military language is full of labels chosen for administrative convenience or operational security. Project names, exercise titles, call signs and database fields may sound suggestive while conveying little about the underlying activity.

US military terminology has defined a “nickname” as a combination of unclassified words assigned an unclassified meaning for administrative, morale or public-information purposes. In other words, the words are labels rather than descriptions.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://irp.fas.org/doddir/usaf/16-701.htm" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: irp.fas.org">[Intelligence Resource Program]</a><span class="citation-popover" role="note"><span class="citation-popover-source">irp.fas.org</span><span class="citation-popover-snippet">Open source on fas.org.</span></span></span>

This matters because ordinary readers naturally interpret language semantically. A phrase containing “star”, “space”, “alien”, “non-terrestrial” or an unusual maritime term can appear to identify the literal subject of a programme. Inside an institution, however, it might instead be:

* an arbitrary project title;
* an exercise faction or scenario role;
* a category covering activity outside a particular [jurisdiction]({{ 'jurisdiction/' | relative_url }});

<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* a technical contrast between land-based and non-land-based assets;
* a temporary label created by a database designer;
* shorthand understood only within one office.

</div>

Internal terminology may also be local rather than organisation-wide. Different departments can use the same term differently, and informal language may never appear in an official glossary. A staff member might invent a memorable heading for a working spreadsheet without intending it as a formal classification.

The wording attributed to McKinnon—particularly “Non-Terrestrial Officers”—shows the problem. Even assuming the phrase was remembered exactly, its literal interpretation is not self-proving. “Terrestrial” can distinguish land from maritime, airborne or space-related assignments; it can also be used loosely or humorously. Establishing the intended meaning would require the original file, its columns and entries, the office that created it and related documents explaining the category. A striking heading without that context is a clue to investigate, not a conclusion.

## Metadata and Authorship Decide What a File Can Prove

The strongest way to evaluate an unusual government file is to reconstruct its provenance: who created it, when, for what activity and in relation to which other records. The US National Archives describes archival record groups in terms of organisational provenance, while its electronic-records requirements define a record partly through the creator, the activity during which it was made or received and its relationship to other records from the same source.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.archives.gov/research/catalog/lcdrg/archival-materials" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: archives.gov">[National Archives]</a><span class="citation-popover" role="note"><span class="citation-popover-source">archives.gov</span><span class="citation-popover-title">National Archives Archival Materials and Related Elements</span><span class="citation-popover-snippet">National Archives Archival Materials and Related Elements</span></span></span>

Useful metadata may include:<span class="citation-chip-wrap"><a class="citation-chip" href="https://www.nist.gov/data-publications/additive-manufacturing-benchmark-2022-schema" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: nist.gov">[nist.gov]</a><span class="citation-popover" role="note"><span class="citation-popover-source">nist.gov</span><span class="citation-popover-title">additive manufacturing benchmark 2022 schema</span><span class="citation-popover-snippet">additive manufacturing benchmark 2022 schema</span></span></span>


<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* the creator and owning office;
* creation, modification and transmission dates;
* version number or approval status;
* email sender and recipient chain;
* directory path and neighbouring files;
* linked attachments;
* document-management identifiers;<span class="citation-chip-wrap"><a class="citation-chip" href="https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: nvlpubs.nist.gov">[nvlpubs.nist.gov]</a><span class="citation-popover" role="note"><span class="citation-popover-source">nvlpubs.nist.gov</span><span class="citation-popover-title">AI.600 1</span><span class="citation-popover-snippet">AI.600 1</span></span></span>
* whether the system was operational, developmental or used for training.

</div>

These details can radically change an interpretation. A document apparently written by an intelligence agency may turn out to be an attachment sent by a private correspondent. A file dated by its upload may reproduce material written decades earlier. A polished memorandum may be an unsigned draft. A personnel table may belong to an exercise database rather than a live administrative system.

Authorship is especially important in declassified collections. The CIA’s reading room includes documents created by or copied from newspapers, consultants, other departments and members of the public. The fact that the CIA retained or declassified an item does not mean that the agency endorsed its contents. Its own collection of historical UFO papers demonstrates that intelligence organisations preserve reports and correspondence because they were received or investigated, not because every reported object was judged extraordinary.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.cia.gov/stories/story/take-a-peek-into-our-x-files" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: cia.gov">[CIA]</a><span class="citation-popover" role="note"><span class="citation-popover-source">cia.gov</span><span class="citation-popover-title">take a peek into our x files</span><span class="citation-popover-snippet">take a peek into our x files</span></span></span>

A screenshot of a few lines rarely preserves enough of this information. A copied phrase is weaker still. Without a complete file and verifiable metadata, investigators cannot reliably establish whether wording was original, whether nearby labels clarified it or whether the material was current when accessed.

## How to Judge an Apparently Extraordinary File

A cautious assessment should begin by asking what the file is, not what its most dramatic phrase seems to imply. Several tests help separate a meaningful disclosure from institutional noise.

**Is it complete?** A partial screen view may omit the heading, footnote, exercise warning or attachment that explains the content.

**Is it final?** Look for signatures, approval records, version numbers and evidence that the document was formally issued rather than merely drafted.

**Who wrote it?** Storage by NASA, the military or an intelligence agency does not prove authorship by that institution.

**What system held it?** Operational, training, development and archival systems serve different purposes and may contain very different kinds of data.

**Can related records confirm the interpretation?** Genuine programmes normally generate connected material: budgets, organisational responsibilities, correspondence, technical documentation or repeated references from identifiable offices.

**Does the unusual reading depend on one ambiguous term?** If an extraordinary conclusion rests mainly on a heading or code name, ordinary institutional meanings must be tested first.

These checks do not prove that every strange file is harmless or mundane. Governments do maintain secret programmes, and incomplete records can contain important evidence. The point is narrower: access to a restricted network does not remove the need for documentary verification. It increases it, because unfamiliar institutional environments contain more specialised shorthand, mixed-status material and simulated content than an outsider can readily recognise.

## Why the Missing Originals Matter

The central weakness in many UFO-hacker stories is not simply that authorities deny the claims. It is that the alleged discoveries cannot be examined in their original digital setting.

In McKinnon’s case, the most famous material was not preserved as a complete document, forensic image or authenticated screenshot available for independent analysis. That prevents basic questions from being answered. Researchers cannot inspect file properties, identify the author, compare revisions, determine the folder’s purpose or search for explanatory records elsewhere in the system.

The absence of an original does not prove that the recollection is false. It does, however, sharply limit what the recollection can establish. Human memory tends to preserve the striking interpretation rather than mundane interface details such as directory names, status fields and document headers. Those apparently minor features are precisely what would distinguish an operational secret from a draft, exercise artefact or test record.

The most defensible conclusion is therefore modest. A hacker may truthfully remember encountering unusual words or imagery on an authentic [government network]({{ 'network-blind-spots/' | relative_url }}) while still misunderstanding what those materials represented. Until the file’s provenance, metadata, authorship and institutional function can be checked, the fact that it came from a government computer is evidence of location—not evidence that its most exotic interpretation is correct.

  function buildUrl(query, reference, marketId) {
    var cfg = markets[marketId] || markets[defaultMarket];
    if (!cfg) return '#';
    var template = String(cfg.url_template || 'https://www.ebay.com/sch/i.html?_nkw={query}');
    var url = template.replace('{query}', encodeQuery(query || '')).replace('{query_plain}', String(query || ''));
    var joiner = url.indexOf('?') >= 0 ? '&' : '?';
    var params = [];
    if (cfg.mkrid) params.push('mkrid=' + encodeURIComponent(cfg.mkrid));
    if (cfg.campaign_id) params.push('campid=' + encodeURIComponent(cfg.campaign_id));
    params.push('mkevt=1');
    params.push('mkcid=1');
    params.push('toolid=' + encodeURIComponent(cfg.tool_id || '10001'));
    if (reference) params.push('customid=' + encodeURIComponent(reference).slice(0, 256));
    return url + joiner + params.join('&');
  }
  function domainLabel(marketId) {
    var cfg = markets[marketId] || markets[defaultMarket] || {};
    return cfg.domain_label || 'eBay';
  }
  function flagClass(marketId) {
    return 'fr-ebay-market-flag fr-ebay-market-flag--' + String(marketId || '').toLowerCase().replace(/_/g, '-').replace(/[^a-z0-9-]+/g, '');
  }
  function closeMenu(section) {
    var menu = section.querySelector('[data-ebay-market-menu]');
    var trigger = section.querySelector('[data-ebay-market-trigger]');
    var picker = section.querySelector('.fr-ebay-market-picker');
    if (menu) menu.hidden = true;
    if (trigger) trigger.setAttribute('aria-expanded', 'false');
    if (picker) picker.classList.remove('fr-ebay-market-picker--open');
  }
  function availableMarkets(section) {
    var select = section.querySelector('[data-ebay-market-select]');
    if (select) {
      return Array.prototype.slice.call(select.options)
        .map(function (option) { return option.value; })
        .filter(function (marketId) { return !!markets[marketId]; });
    }
    return Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]'))
      .map(function (button) { return button.getAttribute('data-ebay-market-button'); })
      .filter(function (marketId) { return !!markets[marketId]; });
  }
  function applyMarket(section, marketId, persist) {
    var available = availableMarkets(section);
    if (available.indexOf(marketId)< 0) marketId = available[0] || defaultMarket;
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-localized-link]')).forEach(function (link) {
      var query = link.getAttribute('data-ebay-query') || '';
      var reference = link.getAttribute('data-ebay-reference') || '';
      link.setAttribute('href', buildUrl(query, reference, marketId));
    });
    var select = section.querySelector('[data-ebay-market-select]');
    if (select && available.indexOf(marketId) >= 0) select.value = marketId;
    var selectedText = marketId;
    if (select && select.selectedIndex >= 0) selectedText = select.options[select.selectedIndex].text;
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-flag], [data-ebay-trigger-market-flag]')).forEach(function (flag) {
      flag.className = flagClass(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-trigger-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-domain-label]')).forEach(function (label) {
      label.textContent = domainLabel(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
      button.setAttribute('aria-selected', button.getAttribute('data-ebay-market-option') === marketId ? 'true' : 'false');
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      var active = button.getAttribute('data-ebay-market-button') === marketId;
      button.setAttribute('aria-pressed', active ? 'true' : 'false');
    });
    section.setAttribute('data-ebay-selected-market', marketId);
    if (persist) {
      try { if (window.localStorage) localStorage.setItem('phoenix-ebay-market', marketId); } catch (err) {}
    }
    closeMenu(section);
  }
  sections.forEach(function (section) {
    if (section.getAttribute('data-ebay-localized-init') === '1') return;
    section.setAttribute('data-ebay-localized-init', '1');
    var available = availableMarkets(section);
    var marketId = defaultMarket;
    if (window.PhoenixAffiliateLocation && window.PhoenixAffiliateLocation.inferMarket) {
      marketId = window.PhoenixAffiliateLocation.inferMarket(available, {
        storageKey: 'phoenix-ebay-market',
        defaultMarket: defaultMarket
      });
    } else if (available.indexOf(defaultMarket)< 0) {
      marketId = available[0] || defaultMarket;
    }
    var select = section.querySelector('[data-ebay-market-select]');
    if (select) {
      select.addEventListener('change', function () {
        applyMarket(section, select.value, true);
      });
    }
    var trigger = section.querySelector('[data-ebay-market-trigger]');
    var menu = section.querySelector('[data-ebay-market-menu]');
    if (trigger && menu) {
      trigger.addEventListener('click', function (event) {
        event.stopPropagation();
        var expanded = trigger.getAttribute('aria-expanded') === 'true';
        menu.hidden = expanded;
        trigger.setAttribute('aria-expanded', expanded ? 'false' : 'true');
        var picker = trigger.closest('.fr-ebay-market-picker');
        if (picker) picker.classList.toggle('fr-ebay-market-picker--open', !expanded);
      });
      Array.prototype.slice.call(menu.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
        button.addEventListener('click', function (event) {
          event.stopPropagation();
          applyMarket(section, button.getAttribute('data-ebay-market-option'), true);
        });
      });
      document.addEventListener('click', function () { closeMenu(section); });
    }
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      button.addEventListener('click', function () {
        applyMarket(section, button.getAttribute('data-ebay-market-button'), true);
      });
    });
    applyMarket(section, marketId, false);
  });
})();
</script>
